## 0. 今日成果冻结与安全前置

- 保留 2026-10-17 有效 API、关节映射、实验量化结果；不把临时 heredoc 覆盖成“已验收版”。
- 先只读快照 FSM (`_Call(7001,"{}")`)、MotionSwitcher、`mode_machine=5`、IMU、关节 q/dq/tau_est、相机和里程计。不要自动 `SetFsmId`、`SelectMode` 或 `SetBalanceMode`。
- 支持人在场、硬件急停可用，不代表存在防跌落装置；机器人工作区清空，任何模式转换前停止动作。
- 不能因脚本里 `input()` 不便使用就改为倒计时自动发动作。实时控制需要单独人工授权与硬件条件检查。

## 1. 固定动作序列（先 Mock/离线回放）

`PRECHECK → OBSERVE_TARGET → ESTIMATE_TARGET_3D → CENTER_PREVIEW → HUMAN_APPROVED_STEP → VERIFY_STOP → BODY_STABLE → TEACH_PREVIEW → ARM_PREGRASP → FINAL_VISUAL_SERVO_PREVIEW → GRASP_VERIFY → RETRACT → DONE`。

任一检测失效/超时/模式不符进入 `SAFE_HOLD`，**不自动跳过到下一阶段**。新旧控制器不得同时写运动 DDS。当前阶段仅运行至 `CENTER_PREVIEW` 和 `TEACH_PREVIEW`。

## 2. RGB-D 对准工位（复用已有 `gdps_qi`）

- 先确认相机确切型号与安装位、RGB/Depth/CameraInfo 可用性、深度单位、时间戳、RGB-depth 对齐、外参 `T_base_camera`、座标约定和可靠实时 TF。
- 检测需维持同一目标 ID；先使用图像主点 `cx,cy` 的偏差 `du,dv`，再将同步深度反投影为相机坐标并用**可信**外参转成 base 坐标，不能把单个像素偏差直接当作躯干/腿部位移。
- 已有 `TargetCenteringController`、`RgbdSyncEvidence`、`ManipulationReadyGate`；禁止另外建立一条未校验像素→电机的捷径。
- 图像中心 ≠ 可抓取：需独立检查地面障碍、机器人停止、身体姿态、手臂工作空间、TCP、相机外参、目标深度噪声及碰撞裕量。
- 腰部的“正面朝向目标”优先以**机器人底座朝向/站姿稳定**与目标相对位姿验证；腰 Pitch/Roll 保留平衡器，不用未验证的腰锁/侧平举动作去强行校正画面。

## 3. 人工示教：先记录，不先开无阻力

- **未知真实“无阻力/拖动示教”模式**：必须由厂家确认支持“站立稳定保持下，只对特定上肢释放阻力/启用重力补偿”的正式流程。未确认前，**禁止手动硬拉通电关节、禁止全身 Damp/torque-off**；只能用只读关节采集记录受控动作。
- 新增 `scripts/g1/g1_arm_readonly_capture.py`：只订阅 `rt/lowstate`，记录左/右臂 15–28 的 `q,dq,tau_est`，另记腰 12–14、mode_machine、时间戳；**绝不发布 `rt/arm_sdk`、`rt/lowcmd`、HandCmd**。
- 记录目标：空载的起始姿态、预抓取点、靠近阶段、虚拟触碰点、退出姿态。每段标注工位目标编号、操作者、动作完成条件、时间戳、相机帧证据；源 JSONL 不覆盖原件、不上传含有隐私的视频。
- `shared/robot_control/g1/teach_trajectory.py`：离线校验单调时间、缺采样、全关节有效值，使用逐关节 Kalman **平滑观察轨迹**，不外推未来动作，不输出可直接下发的电机命令。
- 动作执行时 `arm_sdk` 权重目标是经实测有效的 **1.0**，必须渐变进入和退出；实际复放控制器还未实现，不把示教记录当可直接发送到机器人上的轨迹。

## 4. 取物任务的控制策略（未来阶段）

1. 固定工位下的示教轨迹先用于**空载离线回放**，夹取的实际位置由 RGB-D 观测修正；示教只能提供先验，不保证工位变化后仍可碰到目标。
2. 机器人必须完成视觉对准、步行停止、姿态稳定且通过工作空间/自碰撞/手臂速度/力矩门禁，才可提交单个上肢动作。
3. 最后微控使用相机外参与末端 TCP 误差闭环，小幅限幅、逐步复核并允许人工停止；未知外参或时延则 `SAFE_HOLD`。
4. 灵巧手 Dex3-1 先只读确认真机左右手消息与设备型号，后续单独做空夹抓取与物体接触验收。不能把关节轨迹完成视作抓取成功。
5. `kp=150`、姿态阈值 0.8 rad、临时动作脚本不可自动继承为认证安全配置。
