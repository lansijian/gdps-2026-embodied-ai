## 本日已明确的动作控制习惯（不是通用安全参数）

- 行走 API：`LocoClient.SetVelocity(vx,vy,omega,duration)`；应用侧仍必须监督超时和发送零速度，不能仅依据 RPC=0 判断真实位移或停稳。
- 自定义手臂：`rt/arm_sdk`，索引 15–21、22–28；`motor_cmd[29].q` 为权重。**用户实际实验表明目标姿态执行时需达到权重 1.0**，不得擅自降为 0.3/0.4 作为正式执行权重。
- **进入权重 1.0 要渐变；退出也要受控交接**。不能硬切 0→1，也不能声称发 20 帧权重 0 即具有硬件级故障保护。
- 腰 12/13/14，尤其 14 的 `tau_est` 与姿态变化需要持续记录；`kp=150` 只保留为实验数据，不固化为默认参数。
- `g1_arm_base.py`、`g1_arm_lift_*.py` 等与事故同批的不安全脚本属于归档材料，严禁直接部署/复跑。
- `g1_leg_module.py` 只是对已知 API 的封装，未获得独立实机运行验收；不得标记已验收。
- **绝不通过全身 Damping/切断腿部力矩来模拟手臂的无阻力示教。** 如果厂家未确认受支持的独立手臂示教模式，只录制现有安全姿态的只读数据，不人工拖拉关节。

## 控制链待确认事项

1. Debug / FSM 501 的真实关系：`SetFsmId(501)=0`、语音播报常规模式，但是没有 `_Call(7001)` 回读；`L2+A` 是否按下不可证实。
2. `MotionSwitcher.CheckMode()` 曾返回 `name='ai'`；不能将其当作调试模式下的实时回读。
3. ArmAction 与 `rt/arm_sdk` 连续交接、腿臂控制组合均未验证。
4. `mode_machine=5` 下的腰部控制竞争、侧平举失败机理未证实。
5. 第一次事故无同步遥测，不能假定单一根因或自动防跌倒能力。

## 正式验收的证据合同

每个动作记录 UTC+本机 monotonic 时间、操作者现场确认、动作前/后 FSM(7001)、MotionSwitcher、mode_machine、IMU、29 电机 q/dq/tau_est、RPC 返回、视觉/里程计反馈、动作中止/停止结果。原始 JSONL、视频、配置与代码提交 SHA 关联归档。历史缺失不得后补成“实测”。
